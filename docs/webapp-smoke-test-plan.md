# 中文 Web 控制台最小下载测试计划

## 1. 目的与边界

本计划用于从 `http://127.0.0.1:5556` 发起一次范围受控、可审计的真实网页任务，验证“页面输入—预检—任务队列—CLI—Zarr—Catalog v8—页面检索”的完整闭环。

本轮只编写测试计划，不提交真实下载任务。任务中心继续只显示由 Web 控制台创建并由 `JobManager` 托管的任务，不读取仓库根部的 `logs` 目录，也不改变现有任务、日志和清理策略。

## 2. 测试环境与固定样例

| 项目 | 固定值 |
|---|---|
| 服务 | `http://127.0.0.1:5556` |
| 正式仓库 | `D:\Project\claude-demo\data_pipeline\S1-GRiTS` |
| Python 环境 | `py312_s1grits_v3` |
| 服务工作区 | `D:\Project\claude-demo\data_pipeline\S1-GRiTS\webapp_output` |
| 工作流 | 逐景时序 `scenes` |
| MGRS 瓦片 | `49RGP` |
| 轨道方向 | 仅升轨 `ASCENDING` |
| 时间 | `2025-01`，仅一个月 |
| 输出目录 | `web_smoke_49RGP_202501_asc` |
| 输出格式 | 仅 Zarr |
| 静态层 | 不生成 |
| 逐轨月合成 | 不生成 |
| 分辨率 | 30 m |
| 并行瓦片数 | 1 |
| 可选波段 | Ratio、RVI、GLCM 均关闭 |

选择一个瓦片、一个方向和一个月，是为了降低下载量、运行时间和失败后的清理成本。实际数据量仍由该月的可用轨道与 Burst 数决定，不能把它视为零成本单元测试。

## 3. 执行前门禁

以下条件必须全部满足，才允许在确认对话框中点击“确认并执行”：

1. 5556 端口只由 `py312_s1grits_v3` 中的正式 `s1grits` 服务监听。
2. `/api/capabilities` 返回 S1-GRiTS `3.0.0`、Catalog Schema `8`，且 `output_root` 精确指向正式 `webapp_output`。
3. 首页、本地 Leaflet、Logo、MGRS 接口和 `/api/tasks` 均返回成功状态。
4. NASA Earthdata/ASF 凭据已在当前服务账户中配置，日志不得输出密码、token 或 API key。
5. 输出盘至少预留 10 GB 空间，并确认没有同名输出目录；不得覆盖既有数据立方体。
6. 当前没有 queued/running 网页任务，避免把并发和资源争用误判为功能失败。
7. `49RGP` 能通过项目内置 `mgrs.parquet` 校验，并在地图上正确定位。

任一门禁失败时停止测试，只记录证据，不通过修改 Catalog、删除成果或提高并发来绕过失败。

## 4. 测试步骤

### A. 页面与只读接口

1. 使用无缓存刷新打开首页。
2. 检查左上角纯图标完整、无文字残片、无圆形硬裁剪、轨道小圆点未被截断。
3. 切换道路/影像底图，确认地图仍能缩放和平移。
4. 放大到 MGRS 可见级别，确认格网标签不与提示条重叠。
5. 打开再关闭 Catalog 对话框，确认顶部 `×` 和底部关闭入口均可用。
6. 刷新任务中心，确认它只返回 Web 任务，不出现仓库 `logs` 中的外部日志。

### B. 无下载的输入与预检

1. 选择“逐景时序”。
2. 输入瓦片 `49RGP`，轨道选择“仅升轨 ASCENDING”。
3. 只选年份 `2025` 和月份 `1`。
4. 输出目录填写 `web_smoke_49RGP_202501_asc`。
5. 保持“仅 Zarr”选中；关闭静态层和逐轨月合成。
6. 高级选项设置 30 m、1 个并行瓦片，关闭全部派生波段。
7. 点击“预检并创建下载任务”，但先不确认执行。
8. 核对规划摘要必须准确显示：1 个瓦片、1 个方向、1 年中的 1 个月、scenes、Zarr-only、无 static、无 smonthly，以及正式工作区内的输出路径。

预检阶段不得出现任务卡片，不得写入最终产品或启动下载进程。若摘要与页面输入不一致，测试立即失败。

### C. 单次确认与任务生命周期

1. 保存预检摘要和浏览器时间戳。
2. 只点击一次“确认并执行”；记录返回的 `run_id`。
3. 确认任务中心只新增一张任务卡，状态依次允许为 `queued → processing → validating → done`。
4. 打开任务日志，检查增量刷新、跟随滚动、手动刷新和完整日志下载。
5. 刷新浏览器，确认同一 `run_id`、阶段和进度仍可恢复，不产生重复任务。
6. 确认日志中敏感字段被替换为 `[REDACTED]`。

对于单方向且不生成静态层的样例，任务应执行一个 `process_scenes` 配置，随后依次执行 Catalog `resync`、`validate` 和 `doctor --strict`。任何子命令非零退出时，任务必须进入 failed，而不能显示 done。

### D. 文件与 Catalog 验收

任务完成后验证：

1. `webapp_output/.webapp/jobs/<run_id>/` 至少包含 `job.json`、`config_01.yaml` 和 `log.txt`。
2. 服务器生成的 YAML 中，`output.base_dir` 必须被限定到本次测试目录，且参数与规划摘要一致。
3. 测试输出根存在 `catalog.parquet`，Schema 版本严格为 v8。
4. 至少存在一个 `49RGP / scenes / ASCENDING / 2025-01` 的有效 Catalog 记录，记录中的 Zarr 路径真实存在。
5. Zarr 至少包含 `time`、`y`、`x` 坐标和 `VV_dB`、`VH_dB` 核心变量；时间非空、唯一且单调递增。
6. 空间分辨率为 30 m，CRS、仿射变换、数组尺寸和 Catalog 的 grid/geometry 字段相互一致。
7. 因选择 Zarr-only，不应生成新的 COG 或 Preview；因关闭附加选项，不应生成 static、smonthly、Ratio、RVI 或 GLCM 产品。
8. 在“目录检索”中选择测试目录，必须通过 Schema v8 检查；按 `49RGP`、`scenes`、`ASCENDING`、`2025-01` 查询时，页面记录数和磁盘/Catalog 核验结果一致。
9. “生成报告”能够给出产品、状态、日期范围和时间缺口摘要，且无路径越界或 Schema 降级。

### E. 刷新与持久化

1. 完成后刷新页面，任务卡仍可读取。
2. 在不运行任务的情况下重启 5556 服务，再确认已完成任务仍保持 done，日志仍可查看。
3. 重启不得重新执行已完成命令，也不得自动扫描仓库根部 `logs`。

## 5. 负向检查（不产生第二个真实下载）

本次只执行不会启动下载的负向检查：

- 输入不存在的 MGRS 编号，预检必须拒绝。
- 输出路径包含绝对路径或 `..`，服务必须拒绝越过 workspace。
- 缺少年/月选择时，页面或预检必须给出明确错误。
- 复用已经消费的一次性 plan token，服务必须拒绝重复创建任务。
- Catalog 选择不含根级 `catalog.parquet` 的目录时，查询和报告按钮必须保持禁用。

取消运行中的真实任务、网络中断恢复和重复月份增量写入属于后续专项测试，不在这个最小烟雾测试中额外消耗下载资源。

## 6. 停止条件与失败处理

出现以下情况之一立即停止：

- 服务进程、环境或输出根指向非正式仓库；
- 凭据失败、ASF 限流持续发生或远端返回异常产品清单；
- 可用磁盘空间低于 10 GB；
- 预检摘要与固定样例不一致；
- 发现同名目录已有需要保留的数据；
- 日志泄露凭据；
- Zarr/Catalog 写入正式测试目录之外；
- Catalog strict doctor 失败。

失败后保留 `run_id`、任务目录、日志和已写入的测试输出用于诊断，不自动删除、不覆盖重跑。修复原因后使用新的输出目录重新测试。

## 7. 证据与通过标准

执行时应保存以下证据：

- 首页与参数填写截图；
- 预检摘要截图或 JSON；
- `run_id`、开始/结束时间和最终状态；
- `job.json`、脱敏日志尾部和 Catalog 校验结果；
- Zarr 维度、变量、CRS、分辨率和时间坐标摘要；
- Catalog 页面筛选结果与报告截图；
- 5556 重启后的任务持久化结果。

只有 A–E 全部通过、任务最终为 done、Catalog strict doctor 通过且没有产生计划外产品时，最小网页下载测试才判定为通过。测试输出在用户确认验收前保留，不自动清理。
