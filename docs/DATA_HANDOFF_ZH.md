# 下载数据怎样交给实验使用者

本文是新生产交付与历史数据补充说明的公共操作规范。已有[只读元数据导出与核验](PROVENANCE_READONLY_ZH.md)、受限的 [S1 月度生产留痕](PROVENANCE_WORKFLOW_ZH.md)及配套 GRiTS-Resolver 读取保护。完整影像交付尚无自动复制／打包入口。代码仓库说明软件能力；每批数据还需自己的处理约定与证据。当前代码、skill、参数模板不能替代历史执行记录。

统一采用 current 指向不可变 release 的结构，不另建重复处理说明。历史导出只向与生产根分离的目录写入，原 Zarr、Catalog 和恢复绑定保持原样。实际覆盖、验收和未知项由各批数据自己的元数据记录；历史导出本身不执行生产任务。

## 收到数据先看什么

1. 阅读数据根或独立配套目录的 `DATASET_README.md`，确认批次、产品定义、时间覆盖、缺口与局限。
2. 从 `provenance/current.json` 找到 `provenance/releases/<metadata_release_id>/`，阅读 dataset.json、variables.json、limitations.json 与证据索引；未知项应为 `null` 并说明原因。已核实的实际生产过程由相应 runs／执行证据记录；历史缺证的部分不补写为确定事实。
3. 用 Catalog 找 store，用来源映射查对应时间层、轨道与源产品。月合成的一层通常对应多景／多 burst，不强行做一对一场景关联。
4. 核对该 release 的 `FILES.sha256`、current 绑定和验收范围，再按原影像读取工具检查小窗口。当前 `provenance verify` 不读取影像块；文件校验通过不等于处理方法或全像元内容已获验证。

旧数据没有这些文件时，先列证据缺口并补充可核验信息；不要根据变量名、数值大小或当前默认值补写确定结论，也不因补文档而重写生产数组。

## 每批数据随附的最小材料

```text
original_dataset/                    # 原数据，P2 不写入
  catalog.parquet
  <tile>/<product>/...zarr/
metadata_companion/                  # P2 的独立导出目录
  DATASET_README.md
  provenance/
    current.json
    releases/<metadata_release_id>/
      dataset.json
      variables.json
      outputs.parquet
      sources.parquet
      source_links.parquet
      evidence/
      limitations.json
      verification.json
      FILES.sha256
```

这是当前 P2 的实际目录结构；metadata_companion 是 metadata_only，不含影像。真正完整交付需同时包含 original_dataset 及配套目录，并保留读取时明确的数据根映射。已有 sidecar 或 receipt 复用、建立索引，不生成第二套事实。材料只在源数据稳定后发布；重复运行须传当前 metadata release 作为预期基准，不静默覆盖其他任务的新说明。

后续续写或替换需按 P3 记录新数据代次，P4 读取端显式重载；旧 release 保留，不能把切换说明版本当成恢复已被覆盖的旧像元。历史补录应注明补录日期，区分当时生成的证据与本次观察；本次 observer 版本不冒充历史生产版本。

### 变量说明、来源表与实际生产记录需要回答的问题

| 内容 | 需记录的字段或说明 |
| --- | --- |
| 适用范围 | dataset ID、批次、tile、track/direction、时间、产品变体；分批生产按批次记录，不能用最后一次修复代表十年 |
| 源产品 | collection、产品级别与处理版本、产品 ID、源地址或稳定资产标识、可取得的大小／摘要 |
| 执行代码 | commit、dirty 状态；如有未提交修改，另存实际源码摘要与可取得的快照；包版本不足以唯一定位代码 |
| 数值输入 | 线性功率／振幅／dB 等明确物理语义和证据；供应商已做的处理与本程序的处理分开 |
| 处理顺序 | 镶嵌、投影、空间滤波、裁剪、对数变换、时间聚合、类型转换的实际顺序和参数 |
| 合成 | nanmedian 等方法、计算域、nodata 规则、有效次数的计数单位、时间戳代表何种日期 |
| 数值输出 | 变量名、物理量、单位、dtype、scale/offset、是否已应用、裁剪范围、缺失值 |
| 网格与质量 | CRS、transform、shape、grid_id、几何分组、质量层和有效性语义 |
| 证据等级 | 已由执行记录确认／仅元数据声明／当前实现参考／未知，并附相对证据路径 |

S1：不得由 `VV_dB` 的变量名推断月度聚合发生在哪个域；不得由 `smonthly_raw_nanmedian` 中的 raw 推断它是原始 SAR 振幅。RTC 上游定标与本程序的数值变换需分别说明。static 与动态产品按成像几何和像元网格配对，不跨轨道共用。

S2：分别记录源资产的 scale/offset、Zarr 保存值和读取端是否又执行变换。说明 nodata 屏蔽顺序及是否 harmonize；参数保留不等于已经运算。跨处理基线可能存在逐景参数差异，不能把数组首景属性盲目用于全时序。SCL 类别值与反射率分开，缺质量不等于晴空。

## 人工执行步骤

1. **生产前冻结**：保存实际配置、完整选景与源属性、执行源码及依赖。分别计算文件摘要，不只登记 Git HEAD。
2. **生产时关联**：记录时间层对应的源集合、实际处理方法与已提交状态；失败／过滤／无源分别记载。
3. **交付时核验**：核对来源—提交—Catalog—时间坐标；按已声明的抽样／全像元范围比对源值与输出值。记录坐标、dtype、公式、顺序和比较结果。
4. **整理与脱敏**：复制明确白名单内的证据。删除凭据及 URL 中的授权字段，保留公开的资产版本、产品身份等查询参数；替换用户目录、主机、内网地址、代理与挂载点。保留产品 ID、公共资产 URL、科学参数、原摘要及适用范围。
5. **打包与复核**：对脱敏后文件计算新摘要，同时保存原证据摘要与变换说明。脱敏副本不得冒称原文件逐字节副本。读取 ZIP 内文件重算哈希并检查链接、敏感模式与条目路径；从最终包核对中文标题及关键说明的可读性，不能把 UTF-8 可解码或哈希通过当作内容正确。

不需要交付私人 SSH skill、聊天记录、代理配置、完整工作目录或未经筛选的日志。固定原始配置若必须脱敏，应另做副本；不要修改已有生产任务的恢复绑定。

## 仓库完善顺序

当前已提供本文、[智能体入口](../agents/skills/s1-data-handoff/SKILL.md) 和 [只读 build/verify 使用说明](PROVENANCE_READONLY_ZH.md)。按以下边界继续：

1. **P1/P2 当前入口**：固定类型的三张关联表；对显式所选 store 只读盘点，在独立目录发布与核验元数据。未知保持未知，不读取影像块，也不自动合并旧范围或生成完整 ZIP。
2. **生产记录**：按 [S1 串行月度工作流](PROVENANCE_WORKFLOW_ZH.md)记录追加／替换代次和恢复。其他模式不能自动视为已覆盖，也不能由最后一次 run_summary 代表全库。
3. **读取保护**：配套使用支持 v2 的 GRiTS-Resolver 0.3.1rc1，按显式元数据根和根映射读取。低层惰性读取、独立日合成和并发生产读取不在该验收范围。
4. **历史覆盖与交付**：在独立 metadata_only 目录扩大覆盖，登记范围、失败项与局限。真实数据、清单及运行证据留在 Git 外；公开测试不能替代每批数据的执行证据。通用 ZIP／完整影像复制不属于本候选功能。
